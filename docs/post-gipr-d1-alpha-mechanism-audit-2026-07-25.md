# Post-GIPR-D1 alpha mechanism audit

Date: 2026-07-25

## Outcome

Select one new source-blind axis for a **source-axis design only**:

**PSIM-D1 — Protocol Specification Intent–Maturity relation.**

PSIM-D1 observes immutable historical versions of specification documents in
the official Ethereum EIPs and Bitcoin BIPs Git repositories. Its proposed
primitive is not price, flow, governance execution, social attention, or code
integration. It is the relation between:

1. what a standards document says is being changed and why;
2. which specification sections and declared dependencies actually change;
3. the causal revision history that existed at that point; and
4. whether the contemporaneous Ethereum and Bitcoin specification streams
   show compatible, independent, or conflicting technical intent.

The later trading hypothesis is that cross-protocol specification maturation,
revision pressure, and semantic disagreement may expose a crypto-wide
innovation/risk regime that is not represented by exchange telemetry or
conventional macro releases. This is a falsifiable source hypothesis only. It
is **not** source support, alpha, profitability, or live-trading evidence.

An independent adversarial review returned **NO-GO for preregistration as
initially stated**. The reviewer found the source axis plausibly new but the
candidate identity, leakage controls, historical parser rules, and cheap
baselines under-specified. This document resolves those design blockers. It
does not authorize source execution. The next unit may only preregister a
sealed source-support evaluator against the exact boundaries below.

No 2020–2023 EIP/BIP commit incidence, proposal blob, metadata value, section
text, dependency, status transition, daily card, BTC row, funding row, future
return, reward, model output, action, trade, PnL, CAGR, or MDD was opened while
selecting PSIM-D1.

## Why PSIM-D1 is materially new

PSIM-D1 is not BCIMS. BCIMS read Bitcoin Core `master` first-parent merge
objects and path surfaces, then failed because a post-2023 merge-subject
grammar did not cover historical subjects. PSIM-D1:

- uses `bitcoin/bips` and `ethereum/EIPs`, not `bitcoin/bitcoin`;
- defines source inclusion from immutable tree paths and blob identities, not
  commit subjects;
- treats each historical specification version as the object;
- uses specification sections, dependencies, and revision topology rather
  than code-integration components; and
- retains every matching path event; a metadata failure rejects the source
  instead of routing the event to a convenient audit-only subset.

PSIM-D1 is not GIPR-D1. It uses no chain logs, governor contracts, proposal
descriptions, executable targets, calldata, lifecycle events, or RPC
transport. The common use of immutable public evidence does not make the
observable the same.

PSIM-D1 is also distinct from GitHub Advisory, Wikimedia, Trollbox/TBASR/TSDR,
and prior attention sources. It uses neither vulnerability records, mutable
pageview/social state, chat messages, nor market-conditioned text selection.

This novelty does not establish economic value. It only makes a clean source
test admissible.

## Frozen historical envelope and traversal

The source interval is:

```text
[2020-01-01T00:00:00Z, 2024-01-01T00:00:00Z)
```

For each repository, the source evaluator must:

1. use the exact remote, branch, sealed tip, and object format above;
2. traverse the sealed tip's complete first-parent chain oldest to newest;
3. compute each commit's tree delta against parent one with rename detection
   disabled and NUL-safe path handling;
4. use the empty tree only if a root commit must be compared;
5. retain only events whose effective committer day is in the frozen source
   interval;
6. read historical blobs by object ID, never from a checkout; and
7. retain raw object IDs and normalized hashes for audit, while keeping them
   out of every later model input.

No pre-2020 proposal blob or event is loaded as warm-up. All causal state uses
an explicit boundary reset:

- `window_revision_count = 0` before the first retained event for a proposal;
- `window_age = PRE_WINDOW` until that first retained event, then counts only
  from the first in-window effective day;
- `stale_age = NO_EVENT_YET` for each protocol before its first retained
  event;
- the old blob of a first in-window `UPDATE` or `DELETE` is parsed only as that
  event's immutable `PRE_WINDOW_BASELINE`; it does not create a synthetic
  earlier event or revision count; and
- dependency state before a proposal's first retained event is
  `PRE_WINDOW_UNKNOWN`, except that an event's own old/new dependency delta may
  be classified from its two historical blobs.

This deliberately sacrifices lifetime-maturity information rather than
guessing from the 2020 boundary or opening a pre-window history after seeing
incidence.

First-parent traversal is a sequencing rule, not a commit-subject grammar. A
merge commit contributes the complete tree delta against its first parent.
Direct commits are equally admissible. Commit subject text cannot add,
remove, or classify an event.

## Frozen event identity and path grammar

The only recognized primary-document paths are:

```text
Ethereum: ^EIPS/eip-([1-9][0-9]*)\.md$
Bitcoin:  ^bip-([0-9]{4})\.(mediawiki|md)$
```

Path matching is byte-exact and case-sensitive. Auxiliary directories,
templates, READMEs, status pages, generated indexes, assets, and process
documents outside these exact path forms do not become primary proposal
events.

Within one commit, changed recognized paths are grouped by
`(protocol, proposal_number)`:

- `CREATE`: no recognized old blob and exactly one recognized new blob;
- `UPDATE`: exactly one recognized old blob and exactly one recognized new
  blob, including a `.mediawiki`/`.md` migration for the same BIP number; or
- `DELETE`: exactly one recognized old blob and no recognized new blob.

More than one recognized old blob or more than one recognized new blob for the
same protocol/number is terminal ambiguity. A recognized path whose embedded
number disagrees with its historical blob preamble is terminal. A duplicate
number represented by multiple recognized paths in one historical tree is
terminal.

The immutable event identity is:

```text
SHA256(
  protocol || NUL ||
  commit_object_id || NUL ||
  canonical_decimal_proposal_number || NUL ||
  old_blob_object_id_or_NULL || NUL ||
  new_blob_object_id_or_NULL
)
```

Every matching path event is retained. Rename detection, commit subjects,
current filenames, or semantic judgment may not silently demote an event.

## Historical blob grammar

Every `CREATE` and `UPDATE` new blob, and every `UPDATE` and `DELETE` old blob,
must decode as strict UTF-8 and expose a syntactically valid historical
preamble:

- EIP: fenced RFC-822/YAML-like front matter with an `eip` field matching the
  path number and historical fields retained exactly as present; or
- BIP: RFC-822-style preamble in the historical `.mediawiki` or `.md` blob
  with a `BIP` field matching the path number and historical fields retained
  exactly as present.

The source stage parses status, type, category, layer, dependency, date, and
section fields as immutable historical tokens. It does **not** validate a
2020–2023 blob against today's EIP-1 or the 2025 BIP-3 vocabulary.

Declared lifecycle status is excluded from PSIM-D1's model-visible maturity
state. This prevents current/final status and later process rules from acting
as labels. If a later semantic stage wants an ordered lifecycle feature, it
must first hash-bind the contemporaneous historical process document version
applicable to each event under a separately committed protocol. PSIM-D1 v1
does not authorize that feature.

A missing preamble, malformed UTF-8, malformed field continuation, number
mismatch, or unparseable dependency list is a source-gate failure. It is not
an audit-only escape hatch.

## Causal availability

Git committer time is object content, not a publication receipt. For each
repository:

1. normalize the commit's committer timestamp to a UTC calendar day;
2. define `effective_day` as the running maximum of that day and all prior
   first-parent committer days; and
3. make the commit available at `12:00:00Z` on the second calendar day after
   `effective_day`.

This `+2 calendar-day` rule is the nominal archive clock, not proof of the
historical push time. Git alone cannot prove that a commit was not authored
locally and pushed much later. PSIM-D1 therefore cannot use the nominal clock
as its primary economic evidence.

The source evaluator must construct four independent schedules, frozen before
incidence:

```text
ARCHIVE_D2  = 12:00Z on effective_day + 2 calendar days
ARCHIVE_D7  = 12:00Z on effective_day + 7 calendar days
ARCHIVE_D30 = 12:00Z on effective_day + 30 calendar days
ARCHIVE_D90 = 12:00Z on effective_day + 90 calendar days
```

A daily source card is cut at `12:05:00Z` and may use only events already
available under the schedule being evaluated. All four schedules must replay
independently and preserve pre-2024 future-append invariance.

Any later historical economic preregistration must use `ARCHIVE_D90` as the
primary clock. `ARCHIVE_D2`, `ARCHIVE_D7`, and `ARCHIVE_D30` are labeled
publication-lag diagnostics only; they cannot support a profitability claim.
PSIM-D1 is rejected if the primary result fails under `ARCHIVE_D90`, even if a
shorter proxy looks favorable. This does not mathematically recover a missing
server receipt, but it prevents the design from presenting the weakest proxy
as exact causal evidence.

For live operation, availability is the later of the historical floor and the
durable local fetch, object verification, extraction, canonical hashing, and
manifest-commit time. A force-push, unreachable sealed ancestor, object-hash
change, default-branch change, or failed integrity check halts the source.
History is never silently rebuilt.

## Deterministic source relation cards

The source stage assigns no market side and uses no LLM. For every UTC
decision day, it produces one deterministic card containing:

- all newly available EIP and BIP version events in canonical order;
- explicit `NO_NEW_EVENT` state for either protocol when applicable;
- `CREATE`, `UPDATE`, and `DELETE` event type;
- causal revision-count, age, and update-gap buckets;
- old/new document-section presence and changed-section bitsets;
- dependency-edge add/remove/stable/conflict categories;
- bounded line-change and changed-section-size buckets;
- protocol-local stale-age buckets; and
- the prior card hash.

Let `E_d` and `B_d` be the canonically sorted event sets newly available on
decision day `d` under one archive schedule. Canonical event order is
`(availability_utc, first_parent_index, proposal_number, event_id)` within
each protocol. Cross-protocol relation units are constructed without a model:

1. if both `E_d` and `B_d` are nonempty, include the complete deterministic
   Cartesian product `E_d × B_d`;
2. if exactly one set is nonempty, pair every new anchor event with the most
   recent opposite-protocol event available during the preceding 90 calendar
   days, breaking a tie by event ID;
3. if no opposite-protocol event exists in that window, pair the anchor with
   `NO_COUNTERPART`; and
4. if both sets are empty, emit exactly one `NO_ANCHOR` relation unit.

No semantic similarity, model score, market state, or later status may choose
the pair. Multiple events are never collapsed into a best-looking pair.

The source preregistration must freeze all bucket edges, section aliases,
canonical ordering, text normalization, daily-card schema, and maximum text
sizes before opening 2020–2023 incidence. Raw counts remain audit evidence;
only frozen categories may reach a later model.

No current status page, current blob, current dependency graph, post-2023
revision, GitHub metadata, price, return, funding, rank, action, or outcome may
enter a source relation card.

## Model-visible boundary

Only a complete source-support pass may authorize a separately frozen
semantic/RLLM stage. That later stage must use one small local model; there is
no analyzer/trader pair.

The semantic unit is the complete daily card and its deterministic relation
units. One model is called once per decision card and must emit one aggregate
relation token from the exact taxonomy:

```text
CONVERGENT_INTENT
COMPLEMENTARY_INTENT
TECHNICAL_TENSION
INDEPENDENT_INTENT
INSUFFICIENT_EVIDENCE
ABSTAIN
```

The definitions are:

- `CONVERGENT_INTENT`: both protocol streams address materially similar
  problems or constraints with compatible technical direction;
- `COMPLEMENTARY_INTENT`: the streams address different layers but the stated
  changes can reinforce the same capability or risk reduction;
- `TECHNICAL_TENSION`: the streams expose incompatible assumptions,
  trade-offs, or security/operability direction;
- `INDEPENDENT_INTENT`: the supplied evidence shows no material semantic
  relation;
- `INSUFFICIENT_EVIDENCE`: a required counterpart or enough changed text is
  absent; and
- `ABSTAIN`: the model cannot ground one of the prior labels in quoted
  model-visible evidence.

The model may receive:

- bounded causal old/new specification-diff text;
- deterministic categorical revision-maturity and dependency-change tokens;
- a finite history of cross-protocol relation cards; and
- current target position.

The model may not receive raw proposal numbers, commit/blob hashes, paths,
timestamps, dates, authors, URLs, fork/upgrade names, activation heights,
prices, returns, PnL, or raw numeric fields. Titles, explicit `EIP-N`/`BIP-N`
references, named releases/forks, dates, hashes, addresses, and URLs must be
redacted under a separately frozen deterministic transform.

At runtime the same constrained response must contain exactly one relation
token and one target:

```text
RELATION=<one frozen relation token>
TARGET=<TARGET_LONG|TARGET_FLAT|TARGET_SHORT>
```

There is no free-form rationale and no second analyzer call. The execution
interface consumes only the target while retaining the relation token for
audit. `ABSTAIN` forces `TARGET_FLAT`.
`INSUFFICIENT_EVIDENCE` forces the target to equal the current target position;
when current position is unavailable at a split boundary it forces
`TARGET_FLAT`.

Deterministic code owns source chronology, redaction, numeric/path bucketing,
market execution, costs, funding, reward, leverage, and strict drawdown.

## Pretrained-future leakage quarantine

Redacting identifiers does not guarantee that a 2026 model cannot recognize a
famous historical proposal from distinctive prose. PSIM-D1 therefore freezes
an outcome-blind quarantine before source incidence:

```text
EIP: 20, 721, 1559, 3675, 4337, 4844, 4895
BIP: 32, 39, 44, 141, 340, 341, 342
```

These proposal events remain in source integrity/support accounting, but any
relation unit containing a quarantined proposal is marked
`MEMORIZATION_EXCLUDED` and can never enter semantic training, RLLM training,
checkpoint selection, inference, reward, or economics. The list may not be
reduced after source incidence.

The separately frozen semantic stage must also run an identity-recovery
challenge before outcomes:

1. from non-quarantined events, select at most 16 events per
   `(protocol, source_year)` by the lowest
   `SHA256(event_id || "PSIM_MEMORIZATION_V1")`;
2. for each event, construct eight candidate proposal IDs: the true ID and
   seven distinct same-protocol, same-year decoys selected by the same hash
   rule;
3. show the frozen base model the exact policy-visible redacted old/new text
   and the eight candidates in hash order;
4. force one candidate choice with no abstention; and
5. repeat against the final fine-tuned model before market outcomes.

Run exact one-sided binomial tests against chance `1/8` for EIP, BIP, and
combined samples. Bonferroni-adjusted `p < 0.01 / 3` for either the base or
fine-tuned model terminally rejects PSIM-D1 before market access. Fewer than 32
eligible challenge events per protocol also rejects the semantic stage as
unverifiable. No redaction repair, proposal removal, alternative model, or
challenge resampling is allowed after the first result.

## Required source-only gates

Before any market, funding, reward, model, action, or outcome access, the next
preregistration must freeze an evaluator with at least these ordered gates:

1. exact remote, branch, tip, symref, object-format, and object-integrity
   validation;
2. complete deterministic first-parent traversal and causal-clock validation;
3. exact path/object grammar and unique proposal-tree identity;
4. strict historical blob/preamble/dependency parsing for every retained
   event;
5. nonzero annual, quarterly, and unique-day support for both protocols under
   frozen minima;
6. non-collapsed event-type, section, dependency, revision-age, revision-gap,
   and size vocabularies under frozen concentration limits;
7. daily-card coverage with explicit stale/no-event states;
8. byte-identical independent replay and canonical manifest hashes;
9. future-append invariance for every pre-2024 event and card;
10. deterministic protocol-swap, within-day-order, proposal-version-pair,
    old/new-direction, section-label, dependency-edge, and availability-shift

11. exact relation-unit pairing, boundary-reset, memorization-quarantine, and
    four-schedule replay;
12. zero access to 2024+ proposal content, BTC, funding, returns, rewards,

13. first-failure terminal publication.

The first failed gate retires PSIM-D1 unchanged:

```text
REJECT_PSIM_D1_UNCHANGED_BEFORE_MARKET_MODEL_OR_OUTCOMES
```

## Later LLM and economic falsification

The LLM is justified only if semantic old/new intent adds transfer value that
deterministic revision topology cannot reproduce. Before any labels or market
outcomes, the later stage must freeze:

- exact local model, tokenizer, weights, hash, quantization, prompt, context
  limit, decoding, seed, abstention, and checkpoint-selection rule;
- mandatory number/title/date/URL/fork/status redaction;
- a metadata/frontmatter-only baseline;
- a path/section/diff-size-only baseline;
- a cadence/revision-topology-only baseline;
- shuffled EIP/BIP daily relation;
- shuffled old/new version pairing;
- future/status-scrub control;
- the exact pre-outcome identity-recovery challenge above; and
- one-protocol ablations.

The candidate fails if cheap deterministic baselines transfer as well as the
model, if either frozen model fails the identity-recovery challenge, if
shuffled relations preserve performance, or if either protocol can be removed
without material loss.

Only after those controls are frozen may a separate economic evaluator bind
TRAIN 2020–2021, TEST 2022, EVAL 2023 by **decision timestamp under
`ARCHIVE_D90`**, realistic costs/funding, absolute return, full-calendar CAGR,
strict MDD, trade count, and untouched OOS reporting. The primary candidate
must meet the repository objective `CAGR / strict MDD >= 3` independently in
TEST and EVAL with positive absolute return; shorter publication-lag schedules
cannot rescue a D90 failure.

Repository-wide BTC outcomes have already been heavily inspected, so any
historical success remains candidate-specific transfer evidence, not a
globally pristine discovery. Live profitability requires prospective source
parity and shadow/live evidence.
